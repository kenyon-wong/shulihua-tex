# 文字卡片图片审计与语义化工作流

本流程处理被OCR误保存为PNG的习题标题、练习标题、章节标签和页眉文字。目标是恢复语义结构，同时避免把公式、题干、图形、表格或双栏错序内容误删。

## 基本原则

1. 原始PDF保持原字节；规范修改只进入Markdown和派生EPUB。
2. 审阅阶段只复制图片，不移动或覆盖 `books/assets/`。
3. 不能仅凭尺寸、文件字节数或单张图片决定删除。
4. 必须检查图片前后完整段落、最近标题、题号连续性、书后答案和原PDF相邻页。
5. 双栏页面不能直接采用OCR输出顺序；标题可能被插入题目、公式或下一节句子中间。
6. 只有等价文字已经恢复且图片引用归零后，才能删除PNG。
7. 每次失败使用新候选目录，保留失败报告和证据。

## 阶段一：建立只读候选集

按分册复制候选图，避免不同分册的同名文件覆盖：

```text
review-root/
├── algebra-2/
├── physics-2/
└── ...
```

清单至少记录：

- 仓库相对路径；
- SHA-256、字节数和尺寸；
- 分册及Markdown引用位置；
- 联系表文件名；
- 人工审核状态。

候选副本必须与仓库原图逐字节一致。

## 阶段二：视觉分类

推荐状态：

- `undecided`：尚未判断；
- `replace_with_heading`：图片是唯一标题，原位恢复Markdown标题；
- `remove_duplicate`：正文已有同名标题，只删图片；
- `relocate_heading`：标题因OCR阅读顺序错位，需要移动到正确题组起点；
- `remove_layout_artifact`：纯页眉或版式噪声，不承载正文语义；
- `keep_image`：公式、图形、表格或其他必须保留的视觉内容。

“纯文字”不等于“可以删除”。例如“练习”图片可能位于下一节句子中间，但原PDF证明它实际属于前一页题组，此时应选择 `relocate_heading`。

## 阶段三：只读上下文审计

建立JSON清单：

```json
{
  "schema_version": "1.0",
  "items": [
    {
      "path": "books/assets/example/fig-p0001-01.png",
      "observed_text": "习题1·1",
      "action": "replace_with_heading",
      "heading_level": 4,
      "evidence": "图片后直接开始第1题，答案区编号一致"
    },
    {
      "path": "books/assets/example/fig-p0002-01.png",
      "observed_text": "练习",
      "action": "relocate_heading",
      "heading_level": 4,
      "target_anchor": "1. 解下列各题：",
      "evidence": "原PDF双栏版面显示标题位于该题组起点"
    }
  ]
}
```

执行：

```bash
python3 scripts/audit_image_text_cards.py \
  --manifest /path/to/manifest.json \
  --report /path/to/read-only-report.json \
  --context-lines 20
```

工具会验证PNG、哈希、唯一Markdown引用、上下文窗口、前后标题及人工决定所需证据；不会修改文件。

## 阶段四：原PDF核对

以下情况必须查看原PDF相邻页：

- 图片位于一句话或一道题中间；
- 图片文字与最近标题不一致；
- 题号重新从1开始但没有文字标题；
- 双栏页面中图片顺序可疑；
- “练习”“习题”“复习题”等标题可能属于上一页或下一栏；
- 书后答案的编号与正文不一致。

标题位置以印刷版面和连续正文为准，不机械套用PDF页码。

## 阶段五：隔离候选修改

先在仓库外生成候选Markdown和统一差异：

- 原位标题：以同层级 `####`/`#####` 标题替换图片行；
- 重复标题：只删除图片行，不新增标题；
- 错序标题：在正确题组起点插入或移动标题，再删除原图片；
- 句中图片：删除后合并被打断的同一段或同一句；
- 视觉内容：保持图片及引用不变。

候选必须验证：

- 决策数等于候选图片数；
- 所有目标引用为0；
- 新标题数量与决策表一致；
- 没有重复标题和空题组；
- 没有顺带改写公式或题干。

## 阶段六：合入和资源删除

人工复核候选差异后才合入规范源。删除PNG前再次确认：

1. 全仓库引用数为0；
2. 图片等价语义已恢复；
3. 审阅副本和SHA-256清单仍保留；
4. 删除清单与决策表完全一致。

## 阶段七：构建门禁

```bash
make epub
make pre-push
```

必须满足：

- 17册源文件和EPUB全部通过；
- 缺失资源、孤立资源均为0；
- 图片资产与引用减少量符合决策表；
- MathML、表格和脚注无意外变化；
- nav与NCX同步。

合订版还必须重新执行确定性双构建、细粒度目录继承、Calibre 8.16.2 smoke、`TextEdit.go_to_anchor()`、WebEngine定位和隐私审计。

## 阶段八：提交与发布

提交说明和发布清单记录：

- 涉及分册与图片数量；
- 各处理类型数量；
- 资源和引用前后统计；
- 原PDF是否改变；
- 构建、Calibre和隐私审计结果；
- Release资产SHA-256。

Release继续遵循“仅发布三本学科合订本（EPUB 与重建 PDF）”的策略。
